闭包（Closure）是编程语言中一个重要的概念，尤其在支持函数式编程的语言（如 Go、JavaScript、Python、Rust）中非常常见。简单来说，**闭包是一个函数 + 该函数引用的外部变量的组合**。这个“外部变量”是定义闭包时所在作用域的变量，即使闭包被传递到其他地方执行，它依然“记住”这些变量。

## 1. 一个直观的 Go 示例

```go
func outer() func() int {
    x := 0                      // x 是 outer 的局部变量
    return func() int {         // 这个匿名函数就是一个闭包
        x++                     // 它引用了外部变量 x
        return x
    }
}

func main() {
    counter := outer()
    fmt.Println(counter()) // 1
    fmt.Println(counter()) // 2
}
```

- `outer` 返回的匿名函数引用了它外部的变量 `x`。
- 每次调用 `counter()`，`x` 的值都被保留并修改。
- 这个 `func() int` + 它捕获的 `x` 一起构成了**闭包**。

## 2. 如何理解闭包？

### 2.1 从作用域角度看

通常，函数内的局部变量在函数执行完后就会被销毁。但闭包“捕获”了外部变量，使得这些变量**与函数绑定**，函数存活时变量也存活。每个闭包实例拥有自己独立的捕获变量副本（或引用）。

### 2.2 从数据结构角度看

在 Go 中，闭包在编译时会被转换为一个结构体，里面包含：
- 函数的地址
- 捕获的外部变量的指针（或值）

例如上面的 `outer` 返回的闭包，底层类似：

```go
type closure struct {
    F uintptr   // 函数地址
    x *int      // 捕获的 x 的指针
}
```

每次调用 `outer` 会创建一个新的 `closure` 实例，拥有自己的 `x`。

### 2.3 从使用场景看

- **延迟执行**（如 `defer`）：
  ```go
  x := 1
  defer func() { fmt.Println(x) }() // 闭包捕获 x，输出 1？不，输出最终值？注意求值时机
  x = 2
  // 输出 2，因为闭包捕获的是 x 的引用
  ```
- **生成器**（如上面的计数器）。
- **封装私有状态**：模拟面向对象的“方法+私有字段”。
- **回调函数**（如 HTTP 中间件、事件处理）。

## 3. Go 中闭包的特殊注意事项

- **捕获的是引用**，不是值。循环中常见的陷阱：
  ```go
  func main() {
      var funcs []func()
      for i := 0; i < 3; i++ {
          funcs = append(funcs, func() { fmt.Println(i) })
      }
      for _, f := range funcs {
          f() // 输出 3 3 3
      }
  }
  ```
  因为所有闭包捕获的是同一个变量 `i` 的地址，循环结束时 `i` 变成 3。  
  **解决方法**：使用 `i := i` 或传参。
- **闭包可能导致内存泄漏**：如果捕获一个大对象的引用，而闭包长时间存活，对象无法被 GC 回收。
- **性能**：相比普通函数调用，闭包有额外的间接访问开销（但通常可忽略）。

## 4. 总结

闭包 = 函数 + 它引用的外部环境变量。它让函数可以“记住”定义时的上下文，是函数式编程的基石，也在 Go 中广泛用于并发、中间件、延迟处理等场景。理解闭包的关键是：**内部函数持有外部变量的引用，延长了外部变量的生命周期**。
