# Go 语言 make 与 new 实现原理、版本演进与使用指南

## 1. 核心概念

`make` 和 `new` 都是 Go 语言的内置函数，用于分配内存，但用途和行为有本质区别：

- **`new`**：分配内存，返回指向类型零值的**指针**。适用于所有类型。
- **`make`**：仅用于切片（slice）、映射（map）、通道（channel）三种引用类型，返回**初始化后的（非零值）实例**，不是指针。

## 2. 数据结构与执行机制

### 2.1 `new` 的实现

`new` 在编译期间根据类型大小调用 `runtime.newobject` 函数：

```go
// runtime/malloc.go
func newobject(typ *_type) unsafe.Pointer {
    return mallocgc(typ.size, typ, true)
}
```

- 分配内存并置零（zeroed）。
- 返回指向该内存的指针。
- 与 `&T{}` 等价，但 `new(T)` 不能像 `&T{}` 那样在复合字面量中初始化字段。

### 2.2 `make` 的实现

`make` 的处理分为三种情况，由编译器转换为对特定运行时函数的调用：

| 类型 | 编译器转换函数 | 作用 |
|------|---------------|------|
| 切片（slice） | `runtime.makeslice` | 分配底层数组并返回切片结构（指针、len、cap） |
| 映射（map） | `runtime.makemap` | 初始化 `hmap` 结构，分配桶数组 |
| 通道（channel） | `runtime.makechan` | 初始化 `hchan` 结构，分配环形缓冲区（无缓冲或带缓冲） |

**示例转换**：
```go
// 源代码
slice := make([]int, 3, 5)

// 编译后近似
slice := runtime.makeslice(typ, 3, 5)
```

- `make` 返回的是**已初始化的实例**，可以直接使用（如 `append`、`len`、`cap` 等）。

## 3. 新老版本设计区别

| 方面 | Go 1.16 及之前 | Go 1.17 及之后 |
|------|----------------|----------------|
| **`new` 实现** | 直接调用 `mallocgc` | 无变化 |
| **`make` 切片优化** | 小容量切片在栈上分配（若未逃逸） | 更智能的逃逸分析，更多小切片在栈上分配 |
| **`make` map 优化** | 创建 map 时预分配溢出桶 | 溢出桶的预分配策略调整，减少内存占用 |
| **`make` channel 优化** | 无缓冲和有缓冲通道分别处理 | 优化了缓冲区的内存对齐，提高缓存友好性 |
| **编译器内联** | 部分 `make` 调用可内联 | 更多场景下可内联，减少函数调用开销 |
| **对泛型的支持** | 无 | `make` 可以用于泛型类型实例化（如 `make([]T, n)`） |

## 4. 注意事项

### 4.1 `new` 不会初始化引用类型的内部结构

- `new(map[string]int)` 返回一个指向 `nil` map 的指针，直接使用会 panic。
- `new(chan int)` 返回 `nil` channel，发送/接收会永久阻塞。
- `new([]int)` 返回 `nil` 切片，可安全使用 `append`（nil 切片可直接 append），但 `len`/`cap` 为 0。

```go
p := new([]int)   // p 是 *[]int，指向 nil 切片
(*p) = append(*p, 1) // OK
```

### 4.2 `make` 只适用于 slice、map、channel

- 对基本类型（如 `int`）使用 `make` 会导致编译错误。
- 对自定义结构体使用 `make` 也不行，应使用 `&T{}` 或 `new`。

### 4.3 使用 `make` 时注意容量与长度的区别

- `make([]int, 5)`：长度=容量=5，初始元素为零值。
- `make([]int, 0, 5)`：长度=0，容量=5，初始为空切片，append 时不会立即分配新数组。

### 4.4 `new` 与 `&T{}` 的区别

- `new(T)` 不能为字段赋初值，只能得到零值。
- `&T{Field: value}` 可以指定初始值，功能更强。

### 4.5 避免不必要的指针间接

- 对于小结构体，直接使用值（`T`）可能比使用指针（`*T`）更高效，因为减少了堆分配和 GC 压力。

## 5. 使用场景的区别

| 特性 | `new` | `make` |
|------|-------|--------|
| **适用类型** | 所有类型（包括基本类型、结构体、数组等） | 仅 slice、map、channel |
| **返回类型** | 指针（`*T`） | 引用类型本身（非指针） |
| **内存初始化** | 仅置零（zeroed） | 执行特定初始化（如 map 的哈希表、slice 的底层数组） |
| **零值可用性** | 对于引用类型（map、chan、slice）零值不可用（nil） | 返回值总是可用的（非 nil） |
| **典型场景** | 需要显式返回指针，或配合其他包要求指针参数 | 创建 slice、map、channel 并直接使用 |

### 5.1 何时使用 `new`？

- 需要指向零值类型的指针，且不需要字段初始化。
- 与 `sync` 包结合：`new(sync.Mutex)` 返回可用的互斥锁（零值可用）。
- 在需要返回指针但不想暴露结构体初始化细节时（如工厂函数）。

### 5.2 何时使用 `make`？

- 创建切片、映射、通道时**必须**使用 `make`（除了字面量语法）。
- 需要指定切片的容量、map 的初始容量或 channel 的缓冲区大小时。

## 6. 最佳实践

1. **优先使用 `&T{}` 代替 `new(T)`**  
   - 当需要为字段赋初值时，字面量更清晰。
   - `new(T)` 仅保留给真正需要零值指针且无需初始化的场景（例如在 `sync.Pool` 中）。

2. **创建 slice/map/channel 始终使用 `make`**  
   - 不要使用 `new`，因为返回的是 nil 引用，容易出错。

3. **预分配容量提升性能**  
   - 已知元素数量时，使用 `make([]T, 0, cap)` 避免多次扩容。
   - 已知 map 大小，使用 `make(map[K]V, hint)` 减少 rehash。

4. **避免对 `new` 返回的指针直接解引用而未检查**  
   - 对于 `new(map[K]V)` 返回的指针，必须先 `*p = make(map[K]V)` 才能使用。

5. **理解逃逸分析**  
   - 小对象在栈上分配性能更好。`new` 或 `&T{}` 可能逃逸到堆，但编译器会优化。

6. **使用 `make` 时注意容量和长度的语义**  
   - 预分配容量但长度为 0 可以延迟初始化元素，避免零值浪费。

## 7. 总结

- **`new`**：分配内存，返回零值指针，适用于所有类型。但对于 slice、map、channel 返回的是 nil，需谨慎。
- **`make`**：仅用于 slice、map、channel，返回已初始化的实例（非指针），是使用这三种类型的唯一正确方式。

在性能优化方面，Go 1.17+ 对 `make` 的底层实现做了多项改进，包括更智能的逃逸分析、内存对齐优化等。日常开发中，应牢记：**make 用于引用类型，new 用于其他类型，但更推荐使用字面量或 `&T{}` 形式**。

> 注：本文档基于 Go 1.18~1.22 源码分析，具体实现细节可能随版本变化，建议查看 `runtime/malloc.go`、`runtime/slice.go`、`runtime/map.go`、`runtime/chan.go`。
